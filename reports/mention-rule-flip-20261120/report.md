# 遮住被叫的昵称后，旧规则会改判多少条？

在旧数据中，1,995 条正类明确由“规则分达到 30”赋予标签。原样重算，再把正文中被叫的昵称换成“@某人”，其中 **50 条（2.51%）**跌破 30 分。这是可疑标签的比例，不能据此推算错标率。替换名字也会改变评论长度。发言者的昵称、账号资料、是否楼中楼和原有点名信息在两次评分中相同。

## 数据与训练

对照 19,317 条旧标签的来源，18,933 条原始观测的总分、账号分、正文分和命中理由均与归档一致。按原标签生成逻辑合并同一条目的来源，只要还有一条来源达到 30 分，标签就不会算作翻转。456 个旧标签缺少可回放的来源，其中 448 个是继承的正类、8 个是继承的负类。另有 4 个继承的正类在可回放记录上跌破 30 分，单独计数。

上一版训练集里，有 39 条明确由规则赋予正标签且符合本次隔离条件。还有 3 条涉及继承的标签，继续保留。此次仅在候选训练中移出上述 39 条，原标签和全部人工判断仍然保存在原处。旧训练集的 13,007 行减少至 12,968 行，其余样本保持原来的相对顺序、权重和正文编码。

新候选只训练一次，沿用上一版的种子、模型参数、放行策略和验证集 1% 规则负类触发预算。新阈值 0.886840066570202 在测试评分前冻结。上一版的冻结阈值为 0.8800823463417595。两版在验证集上均触发 18/1,809 条规则负类。

## 复现

在仓库根目录运行。需要私有原始采集导出、上一轮本地训练产物、Node.js 和项目已有的 Python 依赖。两个输出目录应使用新的路径。

~~~text
python code/experiments/mention-rule-flip-20261120/audit.py --workspace <项目工作区> --output <审查输出目录>
python code/experiments/mention-rule-flip-20261120/train.py --workspace <项目工作区> --audit-dir <审查输出目录> --output <训练输出目录>
~~~

本地审查目录提供逐条评分及 50 条可疑评论清单，训练目录提供各划分的配对预测。公开仓库只保存代码、聚合结果与冻结参数。
